Events · send documented commands

Send supported LEGO Wireless Protocol hub actions and request hub event notifications. These are protocol commands, not custom animations or text messages.

Connect Mario to enable event commands.

Compatibility notice: All commands are based on documented LEGO protocol operations, but they cannot be guaranteed to work on Mario. Firmware, hardware capabilities and the connected hub state can affect support. A successful Bluetooth write only confirms that the browser sent the packet; it does not guarantee that Mario performed the action.

Receive-only events: Attached I/O notifications (detached, attached, virtual attached) and hub action notifications (will switch off, will disconnect, will enter boot mode) originate from the hub. This page can display them when received; it cannot send them to Mario as commands.

Not included: production-only shutdown, firmware/bootloader commands, undocumented actions, or arbitrary event injection.

Hub controls

Hub actions and status requests. The official BUSY action controls an RGB indication, not Mario’s LCD screen.

Connect Mario to enable hub controls.

The official BUSY actions (0x05/0x06) request an RGB BUSY indication and preserve prior RGB settings. They do not display text on Mario’s screen. Hardware support for a visible RGB indicator is not guaranteed by the specification. These actions have no success acknowledgement defined: “sent” means the browser wrote the packet, not that an indicator visibly changed.

Display limitation: The published standard LEGO Wireless Protocol defines hub properties/actions and port/sensor/motor messaging, but no standard command for writing arbitrary text or graphics to LEGO Mario’s belly LCD. Mario’s display is not exposed as a normal LPF2 output port in the documented message set. The monitor therefore cannot change the screen through a documented normal-hub command. This may require a separate Mario-specific firmware interface that is not part of the published standard protocol.
Output-command limitation: LWP also defines port output commands (0x81), combined input setup (0x42), and virtual-port synchronization (0x61). This monitor focuses on inspection and sensor input; it does not add generic motor-output controls because those commands can cause connected mechanisms to move unexpectedly.
Camera limitation: LEGO Mario does not expose a camera image stream. The “Sensor view” is an honest visualization of sensor packets, not a live video feed. Unknown values are shown as raw bytes rather than guessed.
